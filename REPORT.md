## Method

The neural backbone is a six-block, width-192, four-head causal GPT with RMSNorm, SwiGLU, untied embeddings, and 8,091,715 trainable parameters. A frozen training-derived bigram residual is added to its logits. Its neural weights were trained from scratch on the supplied training split, not copied from an external model. The checkpoint also contains static continuation tables derived from the same training split:

- Frequent 2–4-token contexts and unique 4-token continuations provide candidate logit bonuses; bonuses are reduced when the neural model already assigns high probability to the candidate.
- Two-token and three-token contexts each retain up to four training continuations and their conditional frequencies. A normalized mixture contributes 0.1 strength from each table, with any unrepresented mass left on the original model distribution.
- Within each independent input window, the predictor searches only earlier observed positions for matching suffixes and mixes a causal empirical next-token distribution. No prefix memory is retained between windows or batch rows.

The final model uses temperature 1.2 and validation-selected scales for n-gram and copy bonuses. The top-four tables and other static memories are serialized within the checkpoint. They do not query the evaluation split or update during inference. For position `t`, every table lookup uses input tokens through `t`; a within-window copied follower comes from an earlier position and is therefore also observed by `t`.

Learned tensors are serialized in FP16 solely to fit the size limit; PyTorch loads them into FP32 CPU modules for ranking. The final score uses FP32 arithmetic, not half-precision inference.

## Training and selection

The selected width-192 backbone was trained for 25,000 updates with batch size 8 and context 256, or **51,200,000 sampled target tokens**. The run used seed 31, AdamW-style updates (beta1 0.9, beta2 0.95, weight decay 0.1), peak learning rate 0.0007, 200-step warmup, cosine decay to 1% of peak, and gradient-norm clipping at 1. The run took approximately 1,407.6 seconds on a local RTX 3050 Laptop GPU. Training used FP32. The static tables were generated by processing the 3,613,343 tokens of the supplied training text; the inherited small-model development lineage used 47,513,600 sampled training targets, and additional exploratory runs are recorded in `results/` and `code/runs/`. Those earlier costs are not presented as part of the selected backbone's 51.2-million-target count.

The supplied baseline, trained with its standard recipe (seed 17; 1,200 updates x 32 examples x 256 targets = 9,830,400 targets), obtained **2.071083 validation BPB**. This initial reference appears in `results/EXPERIMENT_LOG.csv`; it establishes that the final model's improvement is not a renamed baseline.

The development process compared architecture changes and then added memory components using validation. A matched 6,553,600-target screen found the six-block width-160 RMSNorm/SwiGLU model (2.053175 validation BPB) better than the width-128 control (2.146729); untied output embeddings brought it to 2.038442. The A14 combination of training n-grams and within-window copying reached 1.666834 validation BPB. Replacing its neural backbone with the wider, separately trained model and adding the conditional tables led to the final 1.547910. All values in this paragraph are development-set scores, not independent generalization estimates.

## Mechanism ablation

The final candidate and an ablation use identical neural weights, bigram table, n-gram tables, and within-window copy behavior. The ablation only sets both training-conditional top-four mixture strengths to zero:

| Predictor | Validation BPB, CPU FP32 |
|---|---:|
| Final: two- and three-token top-four mixtures at 0.1 each | **1.547910** |
| Same weights, both mixtures disabled | 1.562329 |

The **0.014419 BPB** difference directly measures the additional top-four mechanism at the selected checkpoint. This is a validation-set ablation after calibration, so it must not be interpreted as an independent test gain. An earlier same-weight A13/A14 ablation found a 0.039032 validation BPB gain from within-window copying (1.705866 to 1.666834). Discarded exploratory changes included a top-four 4-token table with a small speed-adjusted gain, dropout fine-tuning, and further low-rate continuation; none entered the frozen submission.

## Reproduce and limitations

```bash
python -m unittest discover -s tests -v
python verify_checkpoint.py --checkpoint ../checkpoint/checkpoint.pt --threads 4
python evaluate.py --checkpoint ../checkpoint/checkpoint.pt --device cpu --precision fp32 --threads 4 --split test
```

The model is close to the 64 MiB checkpoint limit and relies on training-corpus continuation statistics that may not help on unrelated domains. Its CPU runtime is below the measured 5× limit but has less margin than the older A14 predictor. Validation-guided calibration and repeated experimentation can overfit validation; only the frozen test result is reported as the final score.
